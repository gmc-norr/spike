Two routes from simulated reads to variant calls

A. BAM route: targeted tests

align.sh: align spike's reads → sim.bam

merge.sh: replace them in the sample's BAM → merged.bam

Call variants on merged.bam

Only the reads near the event are aligned, with the bwa-mem2 options read from the sample's @PG header line.

B. FASTQ route: full pipeline

spike --into-fastq runs fastq.sh on the raw FASTQ pair

Whole-sample FASTQ with the replaced reads and their duplicates swapped out

Run the clinical pipeline (e.g. nf-core/raredisease) from FASTQ

The pipeline aligns, marks duplicates and calls exactly as it does for any sample.

Route A is for quick, focused tests: align only spike's reads and swap them into the existing BAM. Route B is for full validation: the whole sample's FASTQ with spike's reads in place of the ones they replace, run through the clinical pipeline from the start. The results in this talk use route A.
